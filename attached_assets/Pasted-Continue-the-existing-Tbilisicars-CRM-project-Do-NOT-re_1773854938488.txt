3. BOOKINGS MODULE
-----------------------------------

This is one of the most important Phase 2 modules.

Booking form must include:

Customer section:
- full name
- phone
- email
- optional country
- optional passport / ID
- optional driving license
- notes

Vehicle section:
- choose by model
- optionally assign a specific vehicle plate
- if no specific vehicle is selected, allow booking by model only

Pickup section:
- pickup location
- pickup date
- pickup time
- pickup type: Airport / Hotel / Address
- if Hotel or Address is selected, show text address field
- also support map/location note field

Dropoff section:
- dropoff location
- dropoff date
- dropoff time
- dropoff type: Airport / Hotel / Address
- if Hotel or Address is selected, show text address field
- also support map/location note field

Booking statuses:
- Pending
- Confirmed
- Delivered
- Returned
- Cancelled
- No Show

Important conflict logic:
- Remove any unnecessary “hand over” logic.
- Conflict should happen only when a vehicle is not actually returned but a new pickup is being attempted.
- Do NOT block future consecutive bookings just because the same vehicle is booked on following dates.
- Example: booking on 17th and booking on 18th is valid if the first one is returned correctly.
- Conflict should be based on real overlapping use or non-returned status, not simple existence of consecutive reservations.

Operational logic:
- if booking is created with specific vehicle assigned, system checks real availability
- if booking is created only by model, specific vehicle can be assigned later
- when booking is marked Returned, vehicle status and location must update automatically
- when booking is Delivered, vehicle should move into active/rented state
- when booking is Cancelled or No Show, availability should be restored accordingly

UI:
- bookings table
- filters by status/date/location/model
- booking detail page
- booking create/edit page
- timeline-friendly display where possible

# TASK — Homepage Featured Cars Should Open Booking With Selected Model

Problem:
Homepage Featured Cars currently navigate to /fleet?modelId=XX.
We want Featured Car card click and CTA button click to open the booking flow directly with that model preselected.

Confirmed code:
- Home.tsx currently uses navigate(`/fleet?modelId=${item.vehicleModelId}`) in two places.
- Booking.tsx already supports vehicleModelId from URL query:
  /booking?vehicleModelId=XX
- Fleet.tsx already uses this same route from its "Book This Car" button.

Goal:
Change Homepage Featured Cars navigation from Fleet to Booking:
  /fleet?modelId=XX
to:
  /booking?vehicleModelId=XX

Files to change:
- artifacts/website/src/pages/Home.tsx
- artifacts/website/src/pages/Booking.tsx only if needed to prevent stale session draft from overwriting URL-provided vehicleModelId

Implementation:

1. In Home.tsx, update BOTH featured car navigation handlers:

Card click:
Before:
navigate(`/fleet?modelId=${item.vehicleModelId}`)

After:
navigate(`/booking?vehicleModelId=${item.vehicleModelId}`)

Keyboard Enter handler:
Before:
navigate(`/fleet?modelId=${item.vehicleModelId}`)

After:
navigate(`/booking?vehicleModelId=${item.vehicleModelId}`)

CTA button click:
Before:
navigate(`/fleet?modelId=${item.vehicleModelId}`)

After:
navigate(`/booking?vehicleModelId=${item.vehicleModelId}`)

2. In Booking.tsx, make sure session draft restore does NOT overwrite URL-provided vehicleModelId.

Current prior fix skips draft restore only when pickupLocationId exists in URL.
Extend that guard so draft restore is skipped when either:
- pickupLocationId exists, OR
- vehicleModelId exists

Logic:
const urlParams = new URLSearchParams(window.location.search);
if (urlParams.get("pickupLocationId") || urlParams.get("vehicleModelId")) {
  try { sessionStorage.removeItem(BOOKING_DRAFT_KEY); } catch {}
  return;
}

This prevents an old draft from selecting a different car than the featured car the user clicked.

Do NOT change:
- pricing
- booking API
- CRM
- Fleet page
- Featured cars CRM management
- vehicle availability logic
- trip/date validation
- booking step logic beyond the draft restore guard

Important:
Do NOT remove the trip-change effect that clears vehicleModelId when user changes trip details in this task. That can be reviewed separately if UX requires it.

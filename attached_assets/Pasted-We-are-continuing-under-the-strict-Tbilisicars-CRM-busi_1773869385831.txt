==================================================
BLOCK 7 GOAL
==================================================

Create a real Accounting module for Tbilisicars that records operational financial entries and supports multi-currency handling for GEL, USD, and EUR.

This must behave like a practical internal business accounting tool for CRM operations.
It is not a full external accounting software and should not be overbuilt.

==================================================
A. MODULE PURPOSE
==================================================

The Accounting module is used to track money movement inside Tbilisicars operations.

It must support:
- recording income entries
- recording expense entries
- supporting 3 currencies: GEL, USD, EUR
- showing original transaction currency
- converting totals into GEL for reporting
- making dashboard/accounting totals operationally useful

The system currency logic must be simple and reliable.

==================================================
B. CORE ACCOUNTING RULES
==================================================

The CRM must support these currencies only:

- GEL
- USD
- EUR

Use symbols in UI where appropriate:
- ₾
- $
- €

Every accounting entry must store:
- entry type (Income / Expense)
- category
- amount
- currency
- converted GEL amount
- entry date
- notes
- related entity if simple and already available
- createdAt / updatedAt if already part of system conventions

Converted GEL amount must be saved at entry creation time so historical calculations remain stable.

Do not recalculate old entries every time the exchange rate changes.

==================================================
C. EXCHANGE RATE LOGIC
==================================================

Accounting totals must be unified in GEL.

Use a simple and reliable exchange-rate approach.

Preferred:
- use a Google exchange rate source or similarly simple live rate source already easily available in project conventions

If that is not cleanly possible without destabilizing the system:
- create a simple exchange-rate table/service
- store rate date
- store USD->GEL and EUR->GEL rates
- use the active rate when creating a new accounting entry

Minimum requirement:
- when entry is created in USD or EUR, system calculates and stores GEL equivalent
- GEL entries store same value as convertedGEL

Do not build a complex financial engine.
Keep it operational and stable.

#61 - Fix audit log silent failure (B6)

Project context:
This is a live production monorepo (Tbilisicars CRM & WEB).
We are applying a minimal fix for confirmed issue B6.
Do not refactor architecture. Do not broaden scope.

What & Why
The `logAudit` fire-and-forget IIFE in `audit.service.ts` currently swallows failures with:
`console.error("[AUDIT LOG ERROR]", err)`

When an audit write fails in production, the log contains no structured context about which entity/action was lost.
We need to replace that generic error output with a structured, grep-able failure log.

Done looks like

* The `.catch()` callback emits:
  `[AUDIT FAILURE] <entityType> <action> | entityId=... | actorId=... | error=...`
* `err.message` is extracted safely using an `instanceof Error` guard
* No other behavior changes
* No lines outside the existing catch block are changed unless required purely to format that catch cleanly
* TypeScript build passes

Out of scope

* No architecture changes
* No function signature changes
* No caller changes
* No new dependencies
* No new logger abstraction
* No retry logic
* No async/await additions
* No changes to request flow or audit semantics

Task
In:
`artifacts/api-server/src/services/audit.service.ts`

Locate:
`logAudit(params: AuditParams): void`

Inside its fire-and-forget async IIFE, replace the existing one-line `.catch()` with a multi-line callback that:

1. Safely derives an error message:

   * `err instanceof Error ? err.message : String(err)`

2. Logs with `console.error` using this exact structure:
   `[AUDIT FAILURE] ${params.entityType} ${params.action} | entityId=${params.entityId} | actorId=${params.actorId} | error=${errorMessage}`

Constraints

* Keep the function return type unchanged
* Do not throw
* Do not await
* Do not touch callers
* Do not modify unrelated code

After change
Run the API TypeScript build and confirm it passes cleanly.

Relevant file

* `artifacts/api-server/src/services/audit.service.ts`

#39 - Drop Off Parking Zone — Inside Form
What & Why
Task #38 added a post-dropoff popup for TBS Airport parking zone selection. This spec requires the parking zone selector to live inside the existing Drop Off form/modal, not as a separate dialog that appears after the form closes.

All backend changes from Task #38 are already correct and are not touched:

createAdminBooking applies vehicle side-effects on DELIVERED (vehicle → RENTED, removed from parking)
dropoffLocation.city is already exposed in the booking API response
Pickup flow already removes vehicle from TBS AIR PARKING via applyAdminBookingStatus
Only one file changes: artifacts/crm/src/pages/BookingDetail.tsx.

Done looks like
The Drop Off modal (HandoverModal) shows an optional "Parking Zone" section at the bottom of the form when the booking's dropoff location is Tbilisi International Airport and the booking has an assigned vehicle
Options inside the form: TERMINAL / OUT / FREE / Skip (default: no selection = skip)
Staff selects zone (or leaves unselected) then clicks "Record Drop Off"
If a zone was selected: after successful Drop Off API call, vehicle is assigned to that TBS AIR PARKING zone via POST /admin/parking; a success toast is shown
If no zone selected (Skip): Drop Off completes normally, no parking POST is made
If parking POST fails after a successful Drop Off: a toast is shown, Drop Off is NOT undone, booking state is NOT corrupted
For all non-airport dropoffs, the Drop Off modal is identical to before — no new UI elements appear
Pick Up modal is completely unchanged
No TypeScript errors in BookingDetail.tsx
Out of scope
Any backend changes (Task #38 backend is already complete and correct)
Pickup flow changes (already correct)
Any other page or file

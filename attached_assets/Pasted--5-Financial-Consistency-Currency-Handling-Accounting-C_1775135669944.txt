==================================================
CHANGE A — VEHICLE REVENUE FIX
==================================================

Current problem:
In the vehicle modal / vehicle history / financial overview, total revenue is incomplete or misleading and currently shows wording like:
- "GEL bookings only"

This is incorrect.

Required behavior:
1. Vehicle revenue must include ALL recorded booking payments linked to bookings of that vehicle
2. It must support all currencies:
   - GEL
   - USD
   - EUR
3. All amounts must be converted to GEL for the vehicle revenue summary using the current project conversion rules:
   - USD × 2.7
   - EUR × 2.9
   - GEL stays as is
4. The final displayed total revenue in vehicle financial overview must always be shown in GEL
5. Remove misleading wording like:
   - "GEL bookings only"
6. Replace with something clear like:
   - "Total Revenue (GEL)"

Important rule:
- Use existing booking/payment relations
- Do NOT create a new financial system
- Do NOT change DB schema
- Only fix calculation + display + freshness

==================================================
CHANGE B — BOOKING PAYMENT SUMMARY FIX
==================================================

Current problem:
In Booking Detail > Payment Summary, Total Paid is visually shown incorrectly in GEL instead of preserving the original booking/payment currency as the main amount.

Example:
- Booking price is €183.60
- Customer paid €183.60
- But Total Paid currently shows GEL amount as the main number

Required behavior:
1. Total Paid must display:
   - primary: original booking/payment currency amount
   - secondary: GEL equivalent
2. Same principle must apply to:
   - Remaining Balance
   - Deposit Received
   - Deposit Returned
   - Total Refunded
   - Net Deposit where relevant
3. Display pattern should be:
   - main line = booking/payment original currency
   - secondary smaller line = GEL equivalent
4. Do NOT replace original amount with GEL
5. The booking price area must remain understandable and consistent with payment summary

Important rule:
- Keep original currency visible as source-of-truth
- GEL equivalent is supplementary, not replacement

CHANGE E — PAYMENT STATUS FIX
==================================================

Current problem:
Statuses like "PREHALF" are unclear and not operationally correct.

Required behavior:
Payment status must be derived from real paid-vs-total logic.

Required rules:
- If total paid = 0 → UNPAID
- If total paid > 0 and total paid < booking total → PARTIAL
- If total paid >= booking total → PAID

Required changes:
1. Remove confusing labels like:
   - PREHALF
2. Replace with clear statuses:
   - UNPAID
   - PARTIAL
   - PAID
3. Apply consistently in:
   - Booking list
   - Booking detail
   - Anywhere else in CRM where booking payment status badge is shown
4. Preserve current badge style language, just fix the logic and labels

Important rule:
- This must be based on real payment totals, not legacy string leftovers

PREFERRED LOGIC
==================================================

Currency conversion for GEL equivalent:
- GEL = amount
- USD = amount * 2.7
- EUR = amount * 2.9

Display rule:
- Original currency amount is the primary value where the payment happened in that currency
- GEL equivalent is the secondary supporting value
- Vehicle revenue summary is an exception: it should be shown as GEL aggregate only

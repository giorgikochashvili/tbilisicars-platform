==================================================
CURRENT BUG
==================================================

Inside Booking Detail > Overview quick edit mode, editing fields such as Notes and clicking Save causes an error toast:

"Invalid request parameters"

This means the quick-edit PATCH request is sending an invalid payload or invalid field values.

==================================================
REQUIRED FIX
==================================================

The quick-edit Save action in Booking Detail must work correctly.

Expected behavior:
- If the user edits Notes only, Save succeeds
- If the user edits Booking Price only, Save succeeds
- If the user edits Currency only, Save succeeds
- If the user edits Pickup/Dropoff locations, Save succeeds
- If the user edits Pickup/Dropoff datetime, Save succeeds
- If the user edits multiple of these together, Save succeeds

==================================================
LIKELY ROOT CAUSES TO CHECK
==================================================

Inspect the BookingDetail quick-edit save flow carefully.

Common likely causes:
1. Placeholder values like "Keep current" are being sent in the payload instead of real IDs or omitted fields
2. pickup/dropoff location values are being sent in the wrong type/shape
3. pickup/dropoff datetime values are being composed incorrectly
4. notes-only save is still including invalid empty/default values for other fields
5. PATCH payload includes undefined / placeholder / malformed values that fail backend validation
6. frontend field names may not exactly match the PATCH booking API schema

==================================================
REQUIRED IMPLEMENTATION BEHAVIOR
==================================================

Quick edit Save must build a clean PATCH payload.

Rules:
- Only send valid values
- Do not send UI placeholder strings like "Keep current"
- If a field is unchanged and not needed, either:
  - omit it from the payload
  - or send the actual current valid stored value
- Ensure location fields are sent as real IDs if the API expects IDs
- Ensure datetime fields are sent in the exact format expected by the existing PATCH booking endpoint
- Ensure notes is sent as plain string correctly
- Ensure price/currency stay valid

Most important:
A simple notes edit must not fail because other unrelated fields in the quick-edit form are invalid.

We are moving to Phase 2 for TBILISICARS CRM&WEB.

Goal:
Fix CRM Booking Detail vehicle assignment behavior so staff can see the originally booked car/model even when a different physical vehicle is assigned, and so Unassign returns the booking display to the originally booked model.

Important rules:
- PLAN ONLY first. Do not implement until the plan is approved.
- Do not change database schema unless you prove it is absolutely required. Prefer no schema changes.
- Do not change pricing, availability, booking creation, emails, PDFs, payment logic, pickup/dropoff status logic, or website booking flow.
- Keep this strictly limited to CRM Booking Detail vehicle assignment/display and the minimal backend validation/update logic needed for it.
- Do not refactor architecture.
- Report exact files you plan to change and why.

Current business issue:
Example:
- Customer originally booked Mitsubishi Attrage.
- Staff assigns a specific vehicle from another model, e.g. Mazda 6 · IK248IK.
- CRM currently shows only Mazda 6 · IK248IK and loses the visible original booked model.
- If staff clicks Unassign vehicle, the booking remains displayed as Mazda 6 instead of returning to Mitsubishi Attrage.

Required behavior:
1) Preserve original booked model
- The booking's originally requested model must remain the customer-selected model.
- Assigning a specific physical vehicle from a different model must not overwrite the original booked vehicleModelId if avoidable.

2) Show original booked car in Booking Detail
- When a specific assigned vehicle exists AND its model differs from the originally booked model, show a small muted/gray line under the assigned vehicle:
  "Original booked car: Mitsubishi Attrage"
- Include brand name if available.
- If the assigned vehicle model is the same as the original booked model, do not show the extra line.

3) Unassign behavior
- Clicking Unassign vehicle should remove only the assigned physical vehicle.
- After unassigning, Booking Detail should display the original booked model again.
- Example:
  Original booked model: Mitsubishi Attrage
  Assigned vehicle: Mazda 6 · IK248IK
  After Unassign: display Mitsubishi Attrage with no plate.

Known technical context from code review:
- booking.vehicleModelId appears to be the model originally associated with the booking.
- booking.vehicle returns the assigned physical vehicle data when vehicleId is set.
- booking.vehicleModelName / booking.vehicleModelBrandName are joined from booking.vehicle_model_id.
- current BookingDetail assign flow appears to PATCH vehicleModelId when assignSelectedModelId differs from booking.vehicleModelId. This may be overwriting the original booked model.
- backend validation may reject assigning a vehicle whose model differs from booking.vehicleModelId unless the model is also patched. We need a safe way to allow replacement vehicle assignment without overwriting original booked model.

Plan requirements:

- Explain how you will show "Original booked car: ..." only when assigned vehicle model differs from booking.vehicleModelName.
- Explain how Unassign will return display to the original booked model.
- Identify any risk to existing bookings where vehicleModelId may already have been overwritten in the past.

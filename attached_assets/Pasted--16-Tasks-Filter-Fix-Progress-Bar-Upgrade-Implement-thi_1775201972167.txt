When navigating from `/crm/tasks?assignee=me` to `/crm/tasks`, the component can stay mounted, `user` does not change, and the effect does not re-run. The assignee filter stays stuck on the current user.

Required fix:
- In `artifacts/crm/src/pages/Tasks.tsx`, replace the current `window.location.search` + `[user]` effect pattern with Wouter `useSearch()`
- Make the assignee filter reactive to URL query string changes
- Behavior must be:
  - `/crm/tasks` → assignee filter resets to `"all"` and UI shows `All assignees`
  - `/crm/tasks?assignee=me` → assignee filter becomes current `user.id`
- This must work:
  - on first page load
  - on refresh
  - when navigating between Dashboard widget and sidebar without unmounting the page
- Do not break any other filters
- Do not create URL/state effect loops
- Do not modify backend requests or task ownership logic

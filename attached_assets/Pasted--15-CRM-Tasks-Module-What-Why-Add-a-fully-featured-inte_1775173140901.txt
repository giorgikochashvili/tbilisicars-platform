#15 - CRM Tasks Module

What & Why
Add a fully-featured internal Tasks module to the CRM so admins and managers can create, assign, and track operational work items, while staff can see their own tasks on the Dashboard and update progress in real time.

This is an already working Replit-built Tbilisicars CRM + Website project.
Extend it carefully and natively.
Do not break or refactor unrelated working systems.
Do not change existing booking, fleet, service, dashboard, website, auth, permissions, layout, routing, or styling logic unless strictly required for this task.

Done looks like
- "Tasks" entry appears in the CRM sidebar
- Tasks page shows stat cards (All, My Tasks, Overdue, Due Today, Completed, Urgent) plus a filterable/sortable table
- Create / edit modal lets you set title, description, assignee, priority, status, progress %, start date, due date, and an optional related entity
- Clicking a table row opens a detail drawer with full task info, editable status/progress, a comment thread, and a chronological activity log
- Dashboard shows a "My Tasks" widget displaying total, overdue, and due-today counts for the current user; clicking navigates to Tasks filtered by assignee
- All data persists to PostgreSQL
- Status "Done" auto-sets progressPercent to 100 and records completedAt
- All important mutations are logged to the activity log
- Admins/managers have full access; staff can only see and update their own tasks
- No regression is introduced anywhere else

Out of scope
- Email or push notifications
- Multi-assignee workflow expansion beyond current structure
- External project-management integrations
- Kanban board, recurring tasks, subtasks, templates

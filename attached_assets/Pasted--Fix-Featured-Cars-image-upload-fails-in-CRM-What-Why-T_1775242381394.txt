# Fix: Featured Cars image upload fails in CRM
What & Why
The new CRM Featured Cars / Homepage Slider module was added successfully, but image upload is broken. In the Create/Edit dialog, uploading the car image fails with:
- "Upload failed"
- "Failed to get upload URL"

This means the upload handshake is failing before the actual file upload completes. The issue is likely in how the Featured Cars page requests the signed upload URL, how it sends auth/cookies, how it builds the request body, or how it reads the storage endpoint response.

Important:
Do NOT refactor unrelated parts.
Do NOT change homepage rendering logic.
Do NOT change booking flow logic.
Do NOT change DB/schema.
Only fix the Featured Cars image upload flow so it works exactly like the already-working upload flow used elsewhere in the CRM.

Goal
Make the Featured Cars image upload work reliably by reusing the exact same upload request + PUT upload + returned object path handling pattern that already works in the Fleet CRM image upload flow.

Done looks like
- In CRM → Featured Cars → Add/Edit item:
  - selecting an image successfully requests an upload URL
  - file uploads successfully
  - saved item stores the correct image path/object path
  - thumbnail/preview displays correctly after upload
- No "Failed to get upload URL" error appears anymore
- Existing Fleet/model/brand image upload behavior remains unchanged
- No unrelated UI or API logic is modified

Inspect first
Before editing, inspect and compare the exact upload flow used in the working Fleet-related image upload code, especially:
- artifacts/crm/src/pages/Fleet.tsx
- the exact helper/function used there to request upload URL
- the exact request endpoint path
- request method
- request body keys
- headers
- whether credentials: 'include' is used
- how the returned response is parsed
- which field is stored after upload (objectPath vs publicUrl vs filePath)
Also inspect:
- artifacts/api-server/src/routes/storage.ts
- artifacts/crm/src/pages/FeaturedSlider.tsx

Required fix
1) In FeaturedSlider.tsx, replace the current image upload logic with the exact same working pattern already used in Fleet.tsx.
2) Make sure the request to the upload-url endpoint uses:
- the exact same endpoint path as Fleet
- the exact same payload structure as Fleet
- the exact same credentials/auth behavior as Fleet
- the exact same response parsing as Fleet
3) Make sure the subsequent PUT upload to the signed URL matches the working Fleet logic.
4) Make sure the final stored image value matches the project’s existing storage convention:
- store the object path / storage path in DB, not a temporary signed URL
5) Make sure preview rendering uses the same image normalization logic/pattern already used in Fleet or website image rendering.

Debug requirement
If the FeaturedSlider implementation currently uses a copied-but-modified upload helper, remove that divergence and reuse the exact known-good logic from Fleet instead of maintaining two similar-but-different versions.

Safety constraints
- Do NOT touch unrelated storage behavior
- Do NOT change storage backend design
- Do NOT change working Fleet uploads unless absolutely necessary
- Do NOT redesign the Featured Cars page
- Do NOT change API contracts unless there is a confirmed bug in how FeaturedSlider is calling an already-existing endpoint
- Keep changes minimal and production-safe

Deliverables
After the fix, report:
- exact root cause
- exact files changed
- what was wrong in FeaturedSlider upload flow
- confirmation that Featured Cars now uses the same upload pattern as Fleet

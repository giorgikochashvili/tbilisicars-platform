# TASK — Fix CRM Assign Vehicle Future Availability Model Visibility

Problem:
In CRM Booking Detail → Assign Vehicle, some models disappear from the model dropdown when all vehicles of that model are currently RENTED, even if those vehicles may be available for the booking’s future dates.

Real case:
- 2 Subaru Crosstrek vehicles are currently rented in Kutaisi.
- Staff wanted to assign a Crosstrek to a future booking on May 3.
- Crosstrek did not appear in Assign Vehicle.
- After adding one new AVAILABLE Crosstrek test vehicle, Crosstrek appeared and all Crosstrek vehicles became visible.

Confirmed root cause:
The model dropdown endpoint logic only returns models that have at least one vehicle with status = AVAILABLE in the pickup city.
This is wrong for CRM future assignment because a currently RENTED vehicle can be assignable for a future booking if there is no date conflict.

Goal:
Assign Vehicle model dropdown must show all models that have vehicles in the pickup city, regardless of current vehicle.status.
Final assignment must still be protected by existing backend booking conflict checks.

Files to inspect/change:
- artifacts/api-server/src/services/admin-fleet.service.ts
- function listAdminModels({ city })
- only the Assign Vehicle model list behavior if possible

Implementation:
In listAdminModels({ city }), find the cityModelIds subquery that currently filters:
vehicle.status = 'AVAILABLE'

Remove this status filter from the city-based model visibility subquery.

After change:
A model appears if it has at least one vehicle located in the pickup city, regardless of whether the vehicle is AVAILABLE, RENTED, RESERVED, MAINTENANCE, or INACTIVE.

Do NOT change:
- listAdminVehicles behavior
- vehicle assignment PATCH logic
- booking conflict checks
- vehicle status transitions
- website vehicle visibility
- Fleet page behavior
- pricing/payment/photo logic
- DB schema

Important:
The existing backend assignment validation must remain:
- validateVehicleBelongsToModel
- checkVehicleConflict for overlapping bookings
So impossible assignments are still blocked.

Done looks like:
1. If all Crosstrek vehicles in Kutaisi are currently RENTED, Crosstrek still appears in Assign Vehicle model dropdown for a future booking.
2. Staff can select the model and see vehicles.
3. If selected vehicle has overlapping booking conflict, backend still blocks assignment.
4. If selected vehicle is free for that future date, assignment succeeds.
5. Website public availability is unchanged.

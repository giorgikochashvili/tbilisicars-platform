# REVISE — Dynamic Roles & Permissions Plan (Critical Corrections)

Your plan is strong and aligned with the existing Tbilisicars CRM architecture. 
However, before moving to Build, you must correct the following critical issues to avoid security risks, inconsistent behavior, and future technical debt.

Do NOT redesign the whole system.
Do NOT change the overall approach.
Only FIX the points below and return the corrected plan sections.

==================================================
1. PERMISSION DEFAULT VALUES (CRITICAL SECURITY FIX)
==================================================

Problem:
Some newly added permission columns are set with default = true, which risks granting unintended access to existing non-admin users during migration.

Fix:
- ALL new permission columns must default to FALSE
- No permission should be implicitly granted by default
- Only the role seeding/backfill process should assign TRUE values

Update:
- Schema section
- Migration/backfill logic
- Explicitly state that Admin role gets full TRUE permissions via seed/backfill

==================================================
2. ROLE SOURCE OF TRUTH (REMOVE ENUM DEPENDENCY)
==================================================

Problem:
The plan keeps adminRoleEnum and introduces fallback mapping for custom roles (e.g. fallback to "rental_agent"), which creates inconsistency and future bugs.

Fix:
- roleId must become the ONLY source of truth for permissions and role identity
- adminRole enum must remain ONLY for backward compatibility / cosmetic display
- DO NOT map custom roles to enum values
- DO NOT use fallback enum values for custom roles

Clarify:
- how UI displays role name (from roles table, not enum)
- enum is no longer used for logic

==================================================
3. ACCESS DENIED BEHAVIOR (CONSISTENCY FIX)
==================================================

Problem:
Plan contains conflicting behavior (redirect vs inline Access Denied).

Fix:
- Use INLINE AccessDenied component (no redirect)
- ProtectedRoute should render AccessDenied if permission fails
- Sidebar should already hide restricted modules

Ensure:
- no crashes
- no confusing redirects
- clean UX

==================================================
4. ROLES API — ACTIVE VS ASSIGNED ROLES (EDGE CASE FIX)
==================================================

Problem:
GET /admin/roles returns only active roles, which can break edit flows if a user already has an inactive role assigned.

Fix:
- API must support returning:
  a) all active roles for selection
  b) PLUS currently assigned role when editing a user (even if inactive)

Clarify:
- either via query param OR dedicated endpoint behavior
- frontend must always be able to display the current assigned role safely

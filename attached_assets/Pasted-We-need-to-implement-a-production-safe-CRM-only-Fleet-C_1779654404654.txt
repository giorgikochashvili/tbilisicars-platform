Visible booking definition:
A booking is visible if its pickup/dropoff range intersects the currently visible calendar range.

7. Color logic
Implement display-only booking bar colors:

- Gray = completed/returned reservation.
  RETURNED -> gray.

- Blue = scheduled/upcoming reservation.
  PENDING or CONFIRMED -> blue, unless it is pickup-overdue by the rule below.

- Green = active/current rental.
  DELIVERED -> green, unless it is dropoff-overdue by the rule below.

- Red = overdue / attention needed only.
  Red must be used for operational overdue, not for canceled history.

Hour-aware overdue rules:
A booking becomes red only after a 4-hour grace period:

Pickup overdue:
- status is PENDING or CONFIRMED
- current time is more than 4 hours after scheduled pickup datetime
- pickup action has not happened yet, meaning status is still PENDING/CONFIRMED

Dropoff overdue:
- status is DELIVERED
- current time is more than 4 hours after scheduled dropoff datetime
- dropoff/return action has not happened yet, meaning status is still DELIVERED

Important:
- This overdue state must be pure display/computed logic only.
- Do not update booking status.
- Do not write overdue state to database.
- Do not trigger notifications.
- Do not create audit logs.
- Do not change pickup/dropoff workflows.

Canceled / No-show:
- CANCELED and NO_SHOW must not be strong red.
- Keep them visible but visually de-emphasized if currently returned:
  dashed border, reduced opacity, muted/neutral style.
- Do not hide them in this phase unless already hidden by existing code.

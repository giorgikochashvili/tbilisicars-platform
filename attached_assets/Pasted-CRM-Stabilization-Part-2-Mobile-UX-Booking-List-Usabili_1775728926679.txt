CRM Stabilization — Part 2: Mobile UX, Booking List Usability, and Navigation Comfort

Project context:
This is the live Tbilisicars CRM&WEB monorepo.
Current priority is CRM-first stabilization for staff operations.
Part 1 already addressed dashboard truth, region scoping, tasks count consistency, and Edit Booking prefill.
Now focus only on the exact UX/mobile issues below.
Do NOT refactor architecture.
Do NOT touch unrelated website/public flows.
Do NOT undo Part 1 changes.
Use the smallest safe implementation.

Goal:
Make the CRM significantly more usable on mobile and remove avoidable friction in the Bookings workflow.

==================================================
ISSUE 1 — MOBILE SIDEBAR SHOULD AUTO-CLOSE AFTER MODULE SELECTION
==================================================

Observed behavior:
On mobile, when the sidebar/drawer is opened and a user selects a module, the sidebar remains open and covers the content.

Required fix:
- In mobile/small-screen drawer mode, selecting a module should automatically close/collapse the sidebar
- Desktop persistent sidebar behavior must stay unchanged
- Do not break current navigation highlighting or active-route behavior

Done looks like:
- On mobile: tap menu → choose module → target page opens and sidebar closes automatically
- On desktop: existing persistent sidebar behavior remains unchanged

==================================================
ISSUE 2 — BOOKINGS PAGE NEEDS PHONE NUMBER SEARCH
==================================================

Observed behavior:
Bookings filters currently include:
- Ref #
- Customer name or email
- Vehicle / plate

But CRM staff also need a separate phone-number search field.

Required fix:
- Add a separate phone search input to the Bookings filters
- Keep it distinct from name/email
- Wire it cleanly into the existing filtering flow
- Do not degrade existing filters or overload one field with too many meanings

Done looks like:
- Staff can search bookings directly by customer phone number
- Phone filter works together with the other existing filters

==================================================
ISSUE 3 — BOOKINGS MOBILE LIST IS TOO WIDE / HARD TO USE
==================================================

Observed behavior:
On mobile, the Bookings page still behaves too much like a desktop table.
Staff must horizontally scroll too much to understand each booking.

Required fix:
- Create a compact mobile-only presentation for booking rows
- Do NOT just shrink the desktop table
- Keep desktop/tablet layout intact unless a small responsive adjustment is necessary
- On mobile, each booking should show the most important information in a compact readable structure with minimal or no horizontal scrolling

Prioritize showing on mobile:
- booking ref
- vehicle/model/plate
- customer
- pickup summary
- dropoff summary
- amount/payment status
- booking status

This can be a stacked compact row/card layout if that is the cleanest solution.

Done looks like:
- On mobile, staff can understand a booking without excessive side scrolling
- Main information is visible in one compact block
- Scanning the bookings list is fast and comfortable

==================================================
ISSUE 4 — BOOKING DETAIL MOBILE OVERVIEW SECTION IS BROKEN
==================================================

Observed behavior:
On mobile, the Booking Detail page Overview section has overlapping/cut-off text and broken spacing/alignment.

Required fix:
- Fix the responsive layout of the Overview section for small screens
- Ensure labels/values stack or collapse cleanly
- Prevent overlap, cut-off values, and unreadable wrapping
- Preserve desktop layout if already acceptable

Done looks like:
- On mobile, the Overview section is fully readable
- Labels and values do not overlap
- Long values wrap correctly
- Layout stays clean and visually consistent with the current CRM design

==================================================
IMPLEMENTATION RULES
==================================================

- First inspect the current implementation and choose the smallest safe fix for each issue
- Preserve the CRM dark design language
- Preserve desktop behavior unless the issue explicitly concerns mobile
- Avoid unnecessary refactors
- Do not rewrite unrelated Bookings logic
- If a mobile-only alternative layout is introduced, keep it isolated and maintainable rather than complicating the desktop table path

Validation checklist:
1. Mobile sidebar closes automatically after navigation
2. Bookings page has a separate phone-number search field
3. Mobile Bookings list is compact and usable without excessive horizontal scrolling
4. Booking Detail Overview section is clean and readable on mobile

At the end, report:
- exact files changed
- root cause found for each issue
- what was fully fixed vs partially fixed

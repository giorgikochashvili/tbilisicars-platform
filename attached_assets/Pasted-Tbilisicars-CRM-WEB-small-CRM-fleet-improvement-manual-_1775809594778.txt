Tbilisicars CRM&WEB — small CRM fleet improvement (manual vehicle region change)

We need a small, surgical improvement in the CRM vehicle detail/profile view.

Business need:
Staff must be able to manually change a vehicle’s main region/location from the vehicle detail/profile screen when needed.

Allowed main regions:

* Tbilisi
* Kutaisi
* Batumi

Sub-locations are not the goal here. This action is for changing the vehicle’s main region assignment only.

---

## REQUIRED UI CHANGE

In the vehicle detail/profile screen/modal, add an action/button:
`Change location`

When opened, staff must be able to choose one of the 3 main regions:

* Tbilisi
* Kutaisi
* Batumi

Use the existing location records for those regions (choose the appropriate main/default location record for each city; do not create schema changes).

---

## BUSINESS RULE / SAFETY RULE

Manual vehicle location change must be blocked if the vehicle is operationally tied to any booking.

That means:

* if the vehicle is assigned to an active/current booking
* or assigned to an upcoming/future booking
* or otherwise has an active reservation that should prevent relocation

then the location change must NOT be allowed.

In that case:

* disable the action or block save
* and show a clear CRM message explaining that the vehicle location cannot be changed while it is assigned to an active or scheduled booking

---

## IMPLEMENTATION RULES

* No schema changes
* No refactor
* No unrelated UI changes
* Keep this limited to fleet/vehicle detail logic only
* Reuse existing API/data patterns where possible
* Do not break current booking assignment logic
* Do not allow unsafe location edits

---

## DONE LOOKS LIKE

* Vehicle detail/profile has a `Change location` action
* Staff can switch the vehicle to Tbilisi / Kutaisi / Batumi
* Change is saved only when the vehicle has no active or upcoming booking assignment
* If the vehicle is tied to a booking, the change is blocked with a clear message
* No regressions in fleet or bookings

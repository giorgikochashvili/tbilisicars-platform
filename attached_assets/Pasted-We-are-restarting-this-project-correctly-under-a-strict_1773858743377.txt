-----------------------------------
A. FLEET STRUCTURE
-----------------------------------

Fleet hierarchy must be:

Brand -> Model -> Vehicle

Definitions:
- Brand = manufacturer (Toyota, Hyundai, etc.)
- Model = bookable/displayable car model (Prius, Camry, RAV4, etc.)
- Vehicle = real physical car unit with plate number

Rules:
- One Brand has many Models
- One Model has many Vehicles
- One Vehicle belongs to one Model

Vehicle fields:
- linked model
- plate number
- current location
- mileage
- status
Optional:
- VIN
- year
- color
- notes
- documents
- photos

Vehicle statuses:
- Available
- Rented
- Reserved
- Maintenance
- Inactive

Model fields:
- linked brand
- model name
- category
- transmission
- fuel type
- seats
- main display image
- pricing basis if supported

-----------------------------------
B. LOCATIONS STRUCTURE
-----------------------------------

Main city structure:
- Tbilisi
- Kutaisi
- Batumi

Sub-locations must support:
- Airport
- Downtown
- future custom meet-and-greet points

Initial required locations:
- Tbilisi Airport
- Tbilisi Downtown
- Kutaisi Airport
- Kutaisi Downtown
- Batumi Airport
- Batumi Downtown

Rules:
- each vehicle has one current location
- booking can start in one location and end in another
- after return, vehicle location updates to booking dropoff location

-----------------------------------
C. CUSTOMERS STRUCTURE
-----------------------------------

Customer fields:
- full name
- phone
- email
- country
- passport / ID
- driving license
- notes

Rules:
- customer can be created separately
- customer can also be created inline during booking creation
- one customer can have many bookings

-----------------------------------
D. BOOKING STRUCTURE
-----------------------------------

Booking must support:

Customer:
- select existing customer OR create new inline

Vehicle reservation logic:
- choose model
- specific vehicle is OPTIONAL, not mandatory
- booking can be created by model only
- specific vehicle may be assigned later

Pickup:
- pickup location
- pickup date
- pickup time
- pickup type: Airport / Hotel / Address
- if Hotel or Address is selected, show address field

Dropoff:
- dropoff location
- dropoff date
- dropoff time
- dropoff type: Airport / Hotel / Address
- if Hotel or Address is selected, show address field

Statuses:
- Pending
- Confirmed
- Delivered
- Returned
- Cancelled
- No Show

Lifecycle:
- Pending -> Confirmed
- Confirmed -> Delivered
- Delivered -> Returned
Alternative:
- Pending/Confirmed -> Cancelled
- Pending/Confirmed -> No Show

Conflict logic:
- conflict exists only if a specific vehicle is already in overlapping active use
- or vehicle has not been returned
- consecutive bookings on different dates are valid if previous booking is returned properly
- do not block future valid reservations just because same vehicle is used on next day

Delivery/return effects:
- on Delivered, assigned vehicle status updates appropriately
- on Returned, vehicle status updates appropriately
- on Returned, vehicle current location becomes booking dropoff location

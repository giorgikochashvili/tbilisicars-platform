Tbilisicars CRM&WEB — correctness + mandatory cross-region fleet visibility fix (all 3 regions, surgical, no refactor)

We are fixing a critical lifecycle correctness issue AND preserving required operational visibility for all 3 main regions:

* Tbilisi
* Kutaisi
* Batumi

Business rule:
A vehicle that is currently rented from one region and will return to another region must remain truthfully located in its current region until RETURNED, BUT it must also be visible in the destination region’s fleet/vehicle list as an inbound vehicle before return.

This must work for all cross-region combinations, not just one example:

* Tbilisi → Kutaisi
* Tbilisi → Batumi
* Kutaisi → Tbilisi
* Kutaisi → Batumi
* Batumi → Tbilisi
* Batumi → Kutaisi

Sub-locations like airport / downtown / hotel delivery do NOT change the main region logic.

## PART 2 — Mandatory destination-region visibility (all 3 regions)

File:
artifacts/api-server/src/services/admin-fleet.service.ts

Goal:
When filtering vehicles by city/region, the result must include:

1. vehicles physically in that region now
2. vehicles inbound to that region from another region

Implementation requirement:

When filters.city is active:

1. Keep existing vehicle query based on vehicle.locationId

2. Add inbound vehicle query for vehicles that:

* are RENTED
* are not already in the result set
* have an active DELIVERED booking
* that booking’s dropoffLocationId belongs to the requested city/region

3. Merge them into the same city/region result list

4. Mark them with:
   inboundToRegion: true

Important:
These inbound vehicles MUST appear in the destination region vehicle list/fleet result.
This is required behavior, not optional.

Do NOT fake current location.
Do NOT modify vehicle.locationId for this.

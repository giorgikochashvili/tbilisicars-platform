Item 1 — Booking Detail Add Payment modal deposit fields

Current issue:
In Booking Detail → Payment History → Add Payment form, staff can register a payment, but deposit amount/currency is not conveniently editable in the same form. Deposit is booking metadata and should be shown/saved consistently.

Business rule:
Deposit is NOT a payment.
Deposit must NOT create booking_payment rows.
Deposit must NOT create accounting_entries rows.
Deposit must NOT count toward Total Paid.
Deposit must NOT reduce Remaining Balance.
Deposit must NOT affect paymentStatus.

Required UX:
Inside the existing Add Payment form/modal, add simple fields:
- Deposit Amount
- Deposit Currency

Do NOT add extra explanatory text.
Do NOT add a separate “Deposit Information” header.
Do NOT remove or change Notes.
Keep the form visually clean and consistent with the existing design.

Expected behavior:
When staff clicks Save Payment:
1. The payment should save exactly as before.
2. The booking.deposit and booking.depositCurrency metadata should also be updated if the deposit fields changed.
3. Payment Summary should immediately show the correct Deposit Amount + currency.
4. Booking Overview deposit fields should show the same saved value.
5. Booking Overview should still allow editing deposit amount/currency.
6. Deposit remains metadata-only and does not affect calculations.

Important sync rule:
There must be only one deposit source of truth:
- booking.deposit
- booking.depositCurrency

Add Payment form and Booking Overview must read/write the same booking-level fields.

Design preference:
Fields should look natural in the current form, for example near Amount/Currency or near Notes.
No extra warning/helper text.
No big section header.
Just simple Deposit Amount and Deposit Currency fields.

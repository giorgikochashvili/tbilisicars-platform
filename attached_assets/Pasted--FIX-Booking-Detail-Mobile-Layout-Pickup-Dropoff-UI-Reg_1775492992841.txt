# FIX — Booking Detail Mobile Layout (Pickup/Dropoff UI Regression)

We have a mobile layout regression in the CRM Booking Detail modal/page after recent updates (pickup/dropoff actions and header buttons).

## Problem

On mobile screens:

* layout is no longer responsive
* content overflows horizontally
* sections are cut or misaligned
* header action buttons (Rental Agreement / Return Sheet / Drop Off) break layout

This is a **frontend-only fix**.
Do NOT touch backend, API, or pricing logic.

---

## Goal

Restore a clean, fully responsive mobile layout for the Booking Detail view.

---

## Required fixes

### 1. Prevent horizontal overflow

* Ensure main container uses:

  * `max-w-full`
  * `overflow-x-hidden`
* Remove any fixed width like `w-[xxxpx]` or `min-w-[xxxpx]` that breaks mobile

---

### 2. Header action buttons (critical)

The buttons:

* Rental Agreement
* Booking Voucher
* Return Sheet
* Drop Off

On mobile:

* MUST wrap to multiple lines
* MUST NOT overflow

Fix:

* container → `flex flex-wrap gap-2`
* each button:

  * `w-full sm:w-auto`
  * or allow wrapping naturally

---

### 3. Booking header section

The top section (Booking #, status, dates):

* must stack vertically on mobile

Use:

* `flex-col sm:flex-row`
* proper spacing (`gap-2` / `gap-3`)

---

### 4. Overview + Payment cards

Cards like:

* Overview
* Payment Summary

Fix:

* ensure:

  * `w-full`
  * no horizontal overflow
  * proper padding (`p-4 sm:p-6`)
* grid layout:

  * mobile: `grid-cols-1`
  * desktop: keep existing

---

### 5. Prevent modal width breaking mobile

If this is a modal:

* ensure:

  * `max-w-[95vw]`
  * `w-full`
  * no hardcoded large width

---

### 6. Scroll behavior

* vertical scroll must work
* no horizontal scroll

---

## Constraints

* DO NOT change structure of components
* DO NOT rename components
* DO NOT touch business logic
* DO NOT affect desktop layout
* ONLY adjust Tailwind classes / layout wrappers

---

## Acceptance Criteria

On mobile:

* no horizontal scroll
* buttons wrap cleanly
* all sections visible
* layout readable and clean
* desktop remains unchanged

---

This is a **UI polish fix only** — keep it minimal and safe.

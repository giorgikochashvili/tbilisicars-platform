PART 1 — PICK UP / DROP OFF PHOTO UPLOAD MUST BE RESILIENT
==================================================

This is the highest priority.

Current concern:
When recording Pick Up or Drop Off, uploaded vehicle photos must not fail silently, must not disappear because of unstable internet, must not break on larger files or multiple files, and must not cause the whole process to be lost mid-operation.

Required behavior:
- Support multiple photos reliably for Pick Up and Drop Off
- Prevent silent failure
- Preserve already entered form data if one file upload fails
- Show per-file upload state: pending / uploading / success / failed
- Show user-visible error if any upload fails
- Allow retry for failed files without resetting the whole form
- Do not allow final submit to complete while required uploads are still actively uploading
- If some files fail, staff must be able to retry or remove only failed ones
- Do not lose the rest of the form state because of file upload issues
- Enforce sane file validation before upload:
  - accept image files only
  - protect against overly large files with a clear validation message
  - do not freeze the UI on many files
- If internet is unstable, uploads should fail gracefully and visibly, never silently
- If possible within current architecture, upload files first, then submit the record only after uploads are confirmed
- Do not create half-broken pickup/dropoff records with missing photo references
- Keep existing storage/backend integration if already working; strengthen the flow instead of replacing the architecture

Implementation guidance:
- Inspect current Pick Up / Drop Off modal/components and upload helpers
- Reuse current upload route/storage mechanism
- Add robust client-side upload queue/state management only where needed
- Keep UI aligned with current CRM design
- Add compact thumbnails / file chips with status and retry/remove actions
- Make sure this works for both Pick Up and Drop Off flows

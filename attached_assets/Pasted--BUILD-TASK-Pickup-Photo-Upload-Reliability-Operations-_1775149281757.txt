PART 1 — PICKUP PHOTO UPLOAD (CRITICAL STABILITY FIX)
==================================================

Problem
During pickup, multiple photos are selected but uploads fail with:
"Some uploads failed"

This is unacceptable for operations.

Required outcome:
Uploads must be extremely reliable under ALL conditions:
- slow internet
- mobile data
- many images (10–30+)
- large image sizes
- unstable connections

==================================================
IMPLEMENTATION REQUIREMENTS
==================================================

1. CLIENT-SIDE RESILIENCE

Improve upload system in pickup/dropoff flow:

- Use upload queue system (not all images in parallel blindly)
- Limit concurrency (e.g. 2–3 uploads at a time)
- Add retry mechanism:
  - auto retry failed uploads (at least 2–3 attempts)
- Track upload status per image:
  - uploading
  - success
  - failed (with retry button)

- NEVER lose selected images from UI if upload fails
- Keep them in memory until success or manual removal

2. LARGE IMAGE HANDLING

- Before upload:
  - compress images on client (reasonable quality)
  - resize if too large (e.g. max width ~1600–2000px)
- Prevent huge file payload failures

3. PROGRESS & UX

- Show per-image progress indicator
- Show global upload status

- Disable final "Record" action ONLY if:
  - there are still uploading images
  - OR failed images not resolved

- Allow:
  - retry failed uploads
  - remove failed images manually

4. SERVER COMPATIBILITY

- Ensure backend endpoint can handle:
  - multiple uploads
  - larger payload safely

- If needed:
  - adjust multer/body limits carefully (without breaking security)

5. DO NOT BREAK EXISTING STORAGE LOGIC

- Keep current storage system (do not redesign storage)
- Just make it reliable

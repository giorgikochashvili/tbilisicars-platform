==================================================
BLOCK 12 GOAL
==================================================

Create a practical internal Alerts system that surfaces important operational events inside the CRM interface.

These alerts must help operations staff quickly see critical issues such as:

- vehicles to be picked up today
- vehicles to be returned today
- overdue returns
- booking conflicts
- service due alerts

This is an internal CRM alert system only.
No external messaging systems are required in this block.

==================================================
A. MODULE PURPOSE
==================================================

The Alerts module is used to surface operational warnings and reminders to CRM users.

Alerts should appear in:

1. A dedicated Alerts page
2. Dashboard alert panel (if safe to add)
3. Small alert counter in the sidebar or header if simple

Alerts must be generated using existing CRM data.

==================================================
B. ALERT TYPES
==================================================

Create the following alert categories:

1. Pickup Today
Vehicles scheduled to be picked up today.

2. Dropoff Today
Vehicles scheduled to be returned today.

3. Overdue Return
Bookings whose dropoff date has passed but status is not "Returned".

4. Booking Conflict
Overlapping bookings for the same vehicle.

5. Service Due
Vehicle service records where next service date or mileage threshold is reached.

Keep alert types structured.

==================================================
C. DATA SOURCES

Use only existing modules:

Bookings module
- pickup date

- status

Fleet module
- vehicle status

Service module
- next service date
- next service mileage if available

Do NOT create duplicate tracking tables unless absolutely required.

Alerts should be calculated dynamically where possible.

==================================================
D. ALERT STRUCTURE
==================================================

Each alert must contain:

- alert type
- vehicle (brand + model + plate)
- booking id if applicable
- region
- alert message
- date/time generated

Example message formats:

Pickup Today:
"Vehicle Toyota Prius (ABC-123) scheduled for pickup today"

Dropoff Today:
"Vehicle Toyota Camry (DEF-456) scheduled for return today"

Overdue:
"Vehicle Toyota RAV4 (GHI-789) is overdue for return"

Booking Conflict:
"Vehicle Toyota Prius has overlapping bookings"

Service Due:
"Vehicle Toyota Prius requires scheduled maintenance"

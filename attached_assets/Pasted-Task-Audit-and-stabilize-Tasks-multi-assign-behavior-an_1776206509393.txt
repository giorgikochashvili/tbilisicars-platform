Task: Audit and stabilize Tasks multi-assign behavior and visibility rules

Context:
This is a live production-connected monorepo fully built in Replit. We have already stabilized core booking, customer, email/PDF, dashboard, and CRM booking edit flows. Now the next operational priority is Tasks behavior.

CRITICAL RULES:
- Do NOT refactor architecture
- Do NOT redesign the Tasks module
- Do NOT implement changes yet unless a real issue is clearly identified
- First map the exact current task assignment and visibility flow
- Keep the eventual fix minimal and surgical

Goal:
Ensure Tasks behave correctly for multi-assignment and visibility:
1. A task can be assigned to multiple staff members if intended
2. Users should not see every task unless business rules explicitly allow it
3. Admin can have full/global visibility
4. Task list, counters, and filters should follow the same visibility logic

Audit Scope:

1. Assignment model
- Identify how tasks are currently assigned:
  - single assignee?
  - multiple assignees?
  - taskAssignments table or equivalent?
- Identify all frontend and backend files that control task assignment

2. Visibility rules
- Determine exactly which users can see which tasks today
- Check whether current behavior differs between:
  - admin
  - non-admin staff
  - "all assigned" / "my tasks" / dashboard widgets
- Identify if all tasks are incorrectly visible to all users

3. Dashboard/tasks counters consistency
- Check whether dashboard task counters use the same visibility rules as the tasks list
- Identify mismatch risks where counters and visible rows can differ

4. Edit/create flow
- Verify whether the task creation/edit UI actually supports selecting multiple staff members
- If not, identify what is missing:
  - backend supports it but UI does not
  - UI supports it but persistence is wrong
  - persistence is correct but visibility is wrong

5. Real issues only
Focus only on real operational issues, especially:
- multi-assign not actually persisting
- all users seeing all tasks incorrectly
- admin/non-admin behavior mismatch
- dashboard/list inconsistency

Output format:
A. Exact backend flow (tables/routes/services)
B. Exact frontend flow (pages/components/hooks)
C. Real issues found only
D. Minimal fix plan only for real issues
E. If no real issues are found, explicitly say: "No fixes required"

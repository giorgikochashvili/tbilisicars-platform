We are working ONLY on Dashboard → Operations readability and information hierarchy improvements for the existing Pickups / Dropoffs sections.

CURRENT PROBLEM
The Operations blocks are usable, but they are not informative enough for fast staff work. Important operational data is present, but its hierarchy is weak and the vehicle plate is not visually prominent enough.

GOAL
Improve the readability, hierarchy, and visibility of key operational data in the existing Pickups / Dropoffs UI, on both desktop and mobile, without bloating the layout or breaking the design.

REQUIRED DATA PRIORITY
The Operations rows/cards should make these fields easier to scan in this approximate priority:

1. Reservation / booking reference
2. Vehicle
3. Vehicle plate number
4. Customer full name
5. Phone number
6. Number of rental days
7. Amount
8. Route / pickup and dropoff locations
9. Time
10. Booking status visibility
11. Payment status visibility

IMPORTANT BEHAVIOR / DESIGN RULES
- Plate number must become more visible than it is now
- Booking status must also be visible inside Operations rows/cards
- Payment status must remain visible
- The layout must stay compact and operationally fast
- Do NOT make the block excessively tall or visually cluttered
- Do NOT break desktop layout
- Do NOT break mobile layout
- Do NOT add new filters or features
- Do NOT change the underlying operations logic or data source

STATUS VISIBILITY REQUIREMENT
Inside Operations rows/cards, staff should be able to see both:
- payment status (example: PAID / UNPAID)
- booking status (example: DELIVERED), displayed clearly and consistently

If a booking is already DELIVERED or another relevant operational status, it should be visibly labeled in the row/card in a clean way that matches the UI style.

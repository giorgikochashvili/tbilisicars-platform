FEATURE BLOCK A — TBS AIR PARKING MODULE
==================================================

Business context:
Tbilisi Airport operations use 3 parking zones:
- TERMINAL
- OUT
- FREE

This must become a new CRM operational module/page for internal staff.

--------------------------------------------------
A1. New CRM module/page: TBS AIR PARKING
--------------------------------------------------

Required:
- Add a new CRM module/page named exactly:
  TBS AIR PARKING
- It should be reachable from the left admin navigation/menu like other CRM modules.
- Keep the same CRM shell/layout and visual language.
- The page should clearly represent the 3 parking zones:
  - TERMINAL
  - OUT
  - FREE

--------------------------------------------------
A2. Parking zone capacities
--------------------------------------------------

Required capacity rules:
- TERMINAL = maximum 5 vehicles
- OUT = maximum 10 vehicles
- FREE = unlimited

Behavior:
- TERMINAL should show FULL when 5 vehicles are currently assigned there
- OUT should show FULL when 10 vehicles are currently assigned there
- FREE never becomes FULL

Also show:
- current occupancy count for each zone
- simple visual clarity for available slots / full state

Examples:
- TERMINAL: 4 / 5
- OUT: 7 / 10
- FREE: 12 vehicles

--------------------------------------------------
A3. Parking vehicle assignment flow
--------------------------------------------------

Staff must be able to add a vehicle into a parking zone through a structured flow.

Required action:
- Add something like:
  Enter Car in Parking
  or
  Add Vehicle to Parking

The vehicle must NOT be entered as free text.
Selection flow must be:

1. Select zone:
   - TERMINAL
   - OUT
   - FREE

2. Select Brand

3. Select Model
   - filtered by Brand

4. Select specific active vehicle from the existing database
   - only choose from actual active vehicles already in the system
   - vehicle list should come from existing fleet data
   - use readable labels such as:
     Brand Model — Plate

Important:
- Do not allow duplicate parking assignment of the same vehicle into multiple zones at the same time
- If the vehicle is already parked in one zone, prevent re-adding it elsewhere unless it is removed first
- If TERMINAL or OUT is already full, block adding another vehicle there

--------------------------------------------------
A4. Remove/delete vehicle from parking
--------------------------------------------------

Required:
- Staff must be able to manually remove a vehicle from a parking zone
- Add a clear remove/delete action on each parked vehicle row/item
- This is for cases where the car physically leaves parking and staff updates the system

--------------------------------------------------
A5. Automatic removal on pickup/delivered
--------------------------------------------------

Critical rule:
If a parked vehicle is rented out and its booking reaches Pick Up / Delivered status, that vehicle must automatically disappear from the parking zone list.

Implementation guidance:
- Connect parking occupancy to the real booking/vehicle workflow
- When a booking for a vehicle is successfully processed as Pick Up / Delivered, remove that vehicle from the parking module automatically
- This should work regardless of whether the vehicle was in TERMINAL, OUT, or FREE

Do not fake this only in UI.
It must be actual data consistency.

--------------------------------------------------
A6. Suggested data model for parking
--------------------------------------------------

Implement this cleanly using a dedicated parking table (or similarly clean schema), not by overloading vehicle status.

Suggested structure:
- parking_zone assignment record for vehicle
- zone name
- vehicle_id
- assigned_at
- assigned_by_admin_id (or current staff/admin user id if available)
- active flag OR remove-on-delete behavior
- timestamps if the project convention supports them

Important:
- Only one active parking assignment per vehicle at a time
- Keep it easy to query current occupancy by zone
- Keep room for future audit/history if possible, but do not overbuild

--------------------------------------------------
A7. TBS AIR PARKING page UX
--------------------------------------------------

The page should make operations simple.

Suggested layout:
- 3 clear zone cards/tabs/columns:
  - TERMINAL
  - OUT
  - FREE
- Each zone shows:
  - occupancy count
  - FULL badge when applicable
  - current parked vehicles list
- Each parked vehicle entry should ideally show:
  - plate number
  - brand/model
  - maybe current location/status if easily available
  - remove action

Also provide one obvious add/enter action for staff.

Do not make the page visually cluttered.

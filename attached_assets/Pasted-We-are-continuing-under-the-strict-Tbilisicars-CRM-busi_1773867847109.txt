Your task now is to implement ONLY the Service / Maintenance module for Tbilisicars fleet operations.

==================================================
BLOCK 6 GOAL
==================================================

Create a real Service / Maintenance module that tracks vehicle maintenance history, mileage-related servicing, and completed service operations.

This must behave like a real fleet maintenance tool, not a generic notes table.

==================================================
A. MODULE PURPOSE
==================================================

The Service module is used by operations/service staff to record completed or active service work for specific vehicles.

The module must support:
- creating service records
- filtering service records
- tracking service categories
- linking service to a specific physical vehicle
- storing service date, mileage, cost, notes, and work performed

==================================================
B. SERVICE CATEGORIES
==================================================

Seed and support these service categories as selectable structured values:

- Oil
- Air Filter
- Saloon Filter
- Brake Pads Front
- Brake Pads Back
- Brake Disk
- Windshield
- Windshield Cleaner
- Brake Fluid
- Transmission Fluid
- Disk Repair
- Tyre Fix
- Tyre Change
- Light Bulbs
- Electric
- Wheel Diagnostic

Do not make these free-text only.
Use structured selectable categories, but allow notes as well.

==================================================
C. SERVICE RECORD REQUIREMENTS
==================================================

Each service record must support:

- vehicle (required)
- service category (required, selectable)
- service date
- mileage at service
- cost
- currency if already supported simply, otherwise GEL is enough for now
- vendor / service provider (optional)
- notes / work description
- status if useful (Completed / Planned / In Progress), but keep simple
- createdAt / updatedAt if already part of system conventions

Vehicle selection must use the real fleet data:
- Brand
- Model
- License plate

Correct example:
- Toyota Prius — ABC-123

Do not allow service records without a linked vehicle.

==================================================
D. FILTERING / LIST VIEW
==================================================

Service page must show a useful list/table of service records.

Required filters:
- by region/location if simple and supported through vehicle current location
- by date range
- by service category
- by vehicle search or plate search

Minimum useful list columns:
- date
- vehicle
- category
- mileage
- cost
- vendor
- status

Do not overcomplicate UI, but make it operationally useful.

==================================================
E. VEHICLE INTEGRATION
==================================================

This is important.

Service records must integrate with vehicles in a meaningful way:

1. A service record belongs to one specific vehicle
2. Service page should use existing fleet data
3. Mileage stored in service records must be visible and meaningful
4. If simple to implement cleanly, vehicle detail view may show service history linkage
   - only if it can be done without destabilizing working fleet pages

Do not overbuild predictive maintenance yet.
First make the service records correct and operational.

==================================================
BLOCK 14 GOAL
==================================================

Create a clear internal payment and deposit tracking system connected to bookings and accounting.

This module must allow CRM staff to track:

- booking payments
- deposits received
- deposits returned
- unpaid balances
- refunds
- partial payments

This is an **internal accounting/payment tracking layer**, not an online payment processor.

==================================================
A. CORE PRINCIPLE
==================================================

Payments must be tied to bookings.

Every payment record must belong to a specific booking.

Do NOT create disconnected payment records.

Payments must integrate with the existing Accounting module where possible.

==================================================
B. PAYMENT TYPES
==================================================

Support the following structured payment types:

- Booking Payment
- Deposit Received
- Deposit Returned
- Refund
- Adjustment (optional if simple)

These should be selectable structured values, not free text.

==================================================
C. PAYMENT RECORD STRUCTURE
==================================================

Each payment record must contain:

- booking_id (required)
- payment type
- amount
- currency (GEL / USD / EUR)
- GEL equivalent if using accounting conversion logic
- payment date
- payment method (Cash / Card / Transfer / Other)
- notes
- createdAt / updatedAt

Payments must preserve original currency and value.

==================================================
D. BOOKING PAYMENT SUMMARY
==================================================

Each booking must show a payment summary.

Minimum fields:

- total booking price (if available)
- total paid
- remaining balance
- deposit received
- deposit returned

Example:

Booking price: ₾350  
Paid: ₾200  
Remaining: ₾150  
Deposit: ₾300 (received)  

This summary must update automatically when payments are recorded.

==================================================
E. PAYMENT ENTRY FLOW
==================================================

CRM staff must be able to add payments from the booking page.

Example flow:

1. Open booking
2. Click "Add Payment"
3. Enter amount, currency, type, method
4. Save payment

After saving:

- payment record must be stored
- booking payment summary must update
- accounting entry should be created if safe to link

==================================================
F. ACCOUNTING INTEGRATION
==================================================

Payments should integrate with the Accounting module.

Preferred behavior:

- Booking Payment → Accounting income entry
- Refund → Accounting expense entry
- Deposit Received → Accounting income entry
- Deposit Returned → Accounting expense entry

Use existing currency handling and GEL conversion logic from Accounting.

Do NOT duplicate accounting logic.

==================================================
G. PAYMENT METHODS
==================================================

Structured selectable values:

- Cash
- Card
- Bank Transfer
- Other

This is for internal reporting.

==================================================
H. BOOKING UI INTEGRATION
==================================================

Inside booking detail page show:

Payment section with:

- payment history table
- add payment button
- booking payment summary

Payment history columns:

- date
- type
- amount
- currency
- method
- notes

Newest payments first.

==================================================
I. REPORTS INTEGRATION
==================================================

Payments must automatically appear in Financial Reports via Accounting.

No separate reporting engine is required.

Existing reports should include these entries automatically.

==================================================
J. VALIDATION RULES
==================================================

Payments must validate:

- amount > 0
- valid currency
- booking exists
- payment type selected
- payment method selected

Prevent obviously invalid data.

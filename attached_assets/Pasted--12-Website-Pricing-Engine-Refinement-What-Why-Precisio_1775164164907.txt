#12 - Website Pricing Engine Refinement

What & Why
Precision upgrade to the existing website pricing system: unify day-counting logic with a well-defined grace period rule and 2-day minimum, wire in the One Way Fee system (DB table already exists but is unconnected), expose a structured price breakdown in quote responses, and add admin CRUD for managing one-way fees. The backend quote remains the single source of truth for pricing.

No schema changes. No changes to unrelated pricing paths (CRM manual bookings, extras standalone pricing).

Done looks like
calculateChargeableDays correctly implements the exact rule: count full 24-hour blocks from pickup to dropoff; if remaining extra time is 0–120 minutes add 0 extra days; if 121+ minutes add 1 extra day; minimum 2 days enforced.
Quote responses include oneWayFee (only when pickup ≠ dropoff and a matching fee row exists, otherwise omitted), and the promo discount applies only to the rental base price, not the one-way fee.
The website pricing sidebar shows "One Way Fee (Drop off in different location)" when quote.oneWayFee > 0.
Booking create endpoint resolves the one-way fee server-side from pickup/dropoff location IDs and persists it to booking.oneWayFee — does not trust a client-supplied value.
CRM Locations page gains a compact, isolated "One Way Fees" management section with add/edit/delete using existing schema fields only.

Out of scope
Frontend reimplementation of the full pricing engine — only a minimal preview helper that mirrors backend logic.
Schema migrations or new columns — oneWayFeesTable (with currency) and booking.oneWayFee already exist.
CRM manual booking pricing or any non-website pricing flows.
Promotions system changes.
Rate plan schema or lookup query changes beyond using the corrected chargeableDays value.

Tasks
Shared day-calculation helper — Create artifacts/api-server/src/lib/pricing.ts with a single exported calculateChargeableDays(pickup: Date, dropoff: Date): number. Rule: compute elapsed milliseconds between pickup and dropoff; divide by 86,400,000 to get full 24-hour blocks (floor); compute remainder minutes; if remainder is 0–120 add 0 extra days, if 121+ add 1 extra day; enforce minimum of 2. No other logic in this file.

Quote endpoint — grace period + one-way fee — Update POST /api/public/quote to: (a) accept pickupLocationId?: number and dropoffLocationId?: number in the body; (b) replace the inline day formula with calculateChargeableDays; (c) when pickupLocationId and dropoffLocationId are provided and differ, query one_way_fees for a matching row and include oneWayFee in the response (omit the field entirely if zero or not found); (d) add oneWayFee into estimatedTotal after promo, so the promo discount base remains rental-only.

Booking create — server-side one-way fee resolution — Update POST /api/public/bookings to: (a) use calculateChargeableDays for the rentalDays value used in extras calculation; (b) resolve the one-way fee server-side by querying one_way_fees using pickupLocationId and dropoffLocationId from the body (same query as the quote endpoint); (c) persist the resolved fee to booking.oneWayFee. Do not read a fee value from the client body.

Frontend — minimal local preview + quote wiring — In Booking.tsx: (a) replace calcDays with an exact mirror of the backend helper (full 24-hour blocks, 0–120 minute grace = no extra day, 121+ = +1 day, minimum 2) used only for the days preview label — not for price calculation; (b) send pickupLocationId and dropoffLocationId in the /api/public/quote POST body; (c) add oneWayFee?: number to the Quote interface; (d) display a "One Way Fee (Drop off in different location)" line in the pricing sidebar when quote.oneWayFee > 0; (e) pass resolvedOneWayFee from the last quote to the booking submission body for audit/logging purposes only — the server ignores it and resolves independently.

Admin One Way Fee CRUD + CRM section — Add createOneWayFee, updateOneWayFee, deleteOneWayFee to admin-locations.service.ts using existing oneWayFeesTable fields (fromLocationId, toLocationId, fee, currency) with no schema assumptions beyond what's already defined. Wire POST /admin/one-way-fees, PATCH /admin/one-way-fees/:id, and DELETE /admin/one-way-fees/:id in admin-locations.ts. In Locations.tsx, add a compact, self-contained "One Way Fees" section at the bottom of the page (table of existing fees with from/to location names, fee, currency, and inline delete; a small add form) — do not restructure or redesign the rest of the page.

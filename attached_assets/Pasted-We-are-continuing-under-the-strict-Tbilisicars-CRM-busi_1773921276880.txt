Your task now is to implement ONLY the Audit / Activity Log layer for Tbilisicars CRM.

==================================================
BLOCK 18 GOAL
==================================================

Create a practical internal Audit / Activity Log system that records important operational changes across the CRM.

The goal is simple:

CRM staff must be able to see:
- who performed an action
- what entity was changed
- what action happened
- when it happened
- key before/after context where useful

This is an internal operational traceability layer.
Do NOT overengineer this into a full enterprise event platform.

==================================================
A. CORE PRINCIPLE
==================================================

Audit logs must capture REAL system actions from existing modules.

Do NOT:
- create fake sample logs
- create disconnected manual notes pretending to be logs
- redesign existing entities

Logs must be generated automatically from real create/update/delete/status-change/payment actions.

==================================================
B. MINIMUM MODULE COVERAGE
==================================================

Implement audit logging for these modules first:

1. Bookings
2. Payments / Deposits
3. Service / Maintenance
4. Customers
5. Fleet / Vehicles
6. Team Management

If one or two are harder to wire fully, prioritize:
Bookings, Payments, Service, Fleet.

==================================================
C. LOG ENTRY STRUCTURE
==================================================

Each audit log entry must store at minimum:

- actor user/admin id if available
- actor name/email if easily available
- entity type
  - booking
  - payment
  - service
  - customer
  - vehicle
  - team_member
- entity id
- action type
  - created
  - updated
  - deleted
  - status_changed
  - payment_added
  - payment_deleted
  - etc.
- timestamp
- short summary message

If safely possible, also store:
- before snapshot (only changed fields or compact JSON)
- after snapshot (only changed fields or compact JSON)

Do NOT store huge blobs unnecessarily.
Keep it operational and readable.

==================================================

Fleet / Vehicles:

- vehicle location changed if already captured through update flow

Team:

- team member updated
- team member deleted/inactivated if supported
